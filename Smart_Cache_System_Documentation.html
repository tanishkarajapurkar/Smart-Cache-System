1. System Overview & Core Capabilities

The Smart Cache System is an enterprise-grade distributed caching engine engineered to solve high-concurrency latency bottlenecks, flash-sale spikes, and origin database exhaustion. Unlike standard reactive caching systems (e.g. Redis LRU/LFU) that only cache items after a slow database query has already occurred, this system implements an active AI Decision & Prediction Layer that predicts what will be requested next, protects the origin during traffic surges, and maintains crash-resilient disk snapshots.

Key Innovations Implemented: 1. Traffic Anomaly Detection & Protection Mode (Auto-scales TTLs 3x and shields origin database).
2. Crash-Resilient Disk Persistence (Dual-memory architecture: in-RAM speed + periodic snapshot persistence to disk).
3. Multi-Tier Hot/Warm/Cold Key Classification (Real-time velocity & acceleration tagging).
4. Multi-Factor AI Eviction Scoring (Replaces naive LRU with continuous economic utility scoring).
5. Reinforcement Learning Token Ledger (Reward tokens for prefetch hits with confidence-based policy fallback).

3. Core Algorithms & Mathematical Formulations

1. Traffic Anomaly Detection & Origin Protection Mode Anomaly Defense

The system maintains a rolling window of recent request arrival timestamps \(\{t_1, t_2, \dots, t_k\}\). The current Requests Per Second (RPS) is computed continuously over a sliding 5-second window:

\text{RPS}_{\text{current}} = \frac{|\{t_i \mid \text{now} - t_i \le 5\text{s}\}|}{5.0}, \quad \text{Anomaly Condition: } \text{RPS}_{\text{current}} > \max(20,\; 2.8 \times \text{RPS}_{\text{baseline}})

Automatic Defense: When an anomaly (e.g. 10x Spike Test) triggers, the system flips to PROTECTION MODE. Cache TTLs are immediately multiplied by \(3\times\) (\(180\text{s} \to 540\text{s}\)), and aggressive pre-warming is initiated to shield the origin database. When traffic normalizes below 12 RPS for \(\ge 12\text{s}\), the system reverts to NORMAL MODE.

2. Multi-Factor AI Eviction Scoring Engine Cache Optimization

Traditional caches rely on naive single-variable LRU (evict oldest) or LFU (evict lowest frequency). The Smart Cache Engine replaces this with a continuous multi-factor AI Utility Score:

\text{Score}(k) = 0.4 \times \text{Hotness}(k) + 0.3 \times \text{Recency}(k) + 0.2 \times \text{Frequency}(k) - \text{SizePenalty}(k)

Where \(\text{Recency}(k) = 1 / (1 + \ln(1 + \Delta t_{\text{lastAccess}}))\), \(\text{Frequency}(k) = \min(1.0, \text{hits}/25)\), and \(\text{SizePenalty} = \min(0.2, \text{size}/512\text{KB})\). Under memory pressure (\(> 90\%\)), the engine evicts the key with the lowest AI score rather than a frequently used item that was momentarily idle.

3. Crash-Resilient Disk Snapshot Persistence Data Resilience

Standard in-memory caches lose all cached data upon process termination or RAM crash. The APTS Cache Engine implements dual-tier persistence:

  • In-RAM Fast Path: Serves lookups and updates directly from high-speed memory maps (< 1ms).
  • Atomic Disk Snapshots: A background daemon serializes non-expired keys, values, and remaining TTLs to Cache_Engine/data/cache-snapshot.json every 10 seconds and upon process signals (SIGINT, SIGTERM).
  • Zero-Downtime Recovery: On boot, the engine detects and parses the snapshot, restoring hot and warm keys into RAM before receiving traffic.
4. Hot / Warm / Cold Tiering Classification Demand Forecasting

Every key in the cache engine is continuously scored based on its request velocity \(V\) (hits / age in seconds) and acceleration \(A\) (\(\Delta V / \Delta t\)):

\text{Hotness}(k) = \min\Big(1.0,\; (V \times 2.0 + \frac{\text{hits}}{10}) \times \frac{1}{1 + \log_{10}(\Delta t_{\text{recency}} + 1)}\Big)

Keys are partitioned into: 🔥 HOT (\(\text{Hotness} \ge 0.5\) or \(\text{hits} \ge 5\)), ⚡ WARM (\(\text{Hotness} \ge 0.2\) or \(\text{hits} \ge 2\)), and ❄️ COLD (\(\text{Hotness} < 0.2\)).

5. Reinforcement Token Reward & Confidence Controller Self-Learning Policy

The system tracks prediction quality via a reinforcement token ledger:

  • +10 Tokens: Awarded when a pre-cached key generates a confirmed cache hit (true positive).
  • -5 Tokens: Deducted if a pre-cached key expires without ever receiving a hit (false positive).
  • Confidence Fallback: If AI confidence \(\text{Acc} < 60\%\), the system falls back to conservative LRU/LFU caching. Once confidence exceeds \(60\%\), adaptive predictive caching takes control.

  5. Show Reinforcement Tokens: Show the 🪙 Reward Tokens pill accumulating tokens as user clicks hit pre-warmed cache.
